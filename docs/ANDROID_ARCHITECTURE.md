# Android 架构说明

Android 版继续使用现有的单一 `:app` 模块。先用实际业务边界拆开跨组件流程；包、Activity、Service 的数量不作为重构是否完成的标准。

## 已落地：键盘交接

- 悬浮球或边缘手势发起常规切换，悬浮搜索交回之前保存的聊天窗口，键盘退出按钮可以明确请求切回并显示原键盘。三个入口共用 `ImeHandoffCoordinator`。
- 协调器是活动请求、轮询、超时、重试与取消的唯一所有者。无障碍服务把窗口/编辑器观察、输入法选择和恢复动作接入协调器，不再维护另一套交接任务。系统回调仍由 IME 和无障碍服务接收。
- 普通收起键盘与显式切回是两条不同路径：普通收起只恢复选择，不重新弹键盘。真机兼容规则和验收路径见 [悬浮搜索回归清单](SEARCH_OVERLAY_REGRESSION.md)。

## 已落地：键盘窗口状态

- `ImeWindowTracker` 合并经过校验的系统窗口快照和自家 IME 生命周期。悬浮球、边缘手势、悬浮搜索从同一份状态读取可见性和键盘上沿，不再同时消费广播和服务回调。
- 自家 IME 隐藏后仍保留 200 ms 的残留窗口保护。窗口读不到时保留上次观测到的可见性和边界：仅悬浮球继续沿用检测失败时允许显示的规则，白名单仍优先；搜索和手势不把观测失败当成键盘收起。

## 接下来要收敛的边界

1. **图片发送**：把发送策略选择、URI 准备与授权、平台投递和诊断分离。现有标准协议、宿主兼容分支、发送失败回退应分别有回归用例；在真机验收前不删分支或修改优先级。
2. **图库数据**：在修改收藏夹、最近使用和资源查询时逐步统一应用页面、IME 与悬浮组件的数据入口；保持现有数据库、导包协议和用户配置兼容。

每个阶段先固定现有行为，再迁移责任、删除重复路径。单元测试验证策略与状态转换；切换键盘、宿主焦点和发图结果仍要在真实设备和目标应用中验证。
