# 悬浮球应用白名单（试用版）

入口：悬浮设置 → 悬浮球 → 仅在白名单应用中启用悬浮球。
使用“选择白名单应用”进入独立列表页，切换应用开关即保存。功能默认关闭。
悬浮球与分享白名单共用页面样式；每次进入时已开启的应用置顶，两组内部按名称、包名排序，当前操作不移动条目。
两个白名单页面均支持按应用名称或包名实时搜索（忽略大小写和首尾空格），搜索框可一键清空。筛选只影响显示，开关修改立即保存，清空搜索后保留最新选择和本次进入时的排序。

## 行为约定

- 关闭白名单：保持原有悬浮球行为。
- 开启白名单：仅核验到已选应用时，才执行原有键盘/自家应用显示逻辑。
- 非白名单、未知窗口、锁屏、熄屏：立即隐藏并禁用触摸，取消正在进行的悬浮球手势；不等待淡出动画或输入法切换保护。
- 自家应用固定加入白名单，界面中标记“固定开启”且不可关闭；已有配置自动生效。未选择其他应用时，仅允许自家应用。
- 键盘窗口不替代宿主应用；系统界面接管焦点/活动状态时隐藏。
- 键盘或自家搜索浮窗接管交互、所有应用均失去焦点/活动标记时，仅在上一已核验宿主仍存在于窗口列表中才沿用它；无历史时仅接受唯一宿主。不会因搜索浮窗属于自家应用就放行未选宿主。
- 分屏、小窗和 PiP 按当前输入焦点应用判断；无应用焦点时使用唯一活动应用。冲突或无法确定时隐藏，新应用焦点优先于历史宿主。
- 球仍是全局悬浮窗，不限制在目标应用窗口范围内，因此可能位于另一侧应用画面上。
- 只限制悬浮球，边缘手势、搜索浮窗保持各自的原有行为。
- 当前用户下有启动入口的应用可供选择；不可用的已选包名保留在列表中，可手动移除。

## 识别和耗电

复用现有无障碍服务的窗口状态/结构变化事件，读取窗口类型、焦点和根节点包名，不遍历页面内容。
不新增使用情况访问权限、不持续轮询、不增加保活服务或唤醒锁。
未知窗口只在事件后最多重试两次（120ms、再过240ms），其间保持隐藏。
前台核验结果不变时不重复分发；已强制隐藏的球不重复更新窗口。
服务重连、白名单配置变化和亮屏解锁也会重新核验。

这是异步全局悬浮窗方案：不能保证系统切换应用的同一帧就完成隐藏。
OEM 窗口上报差异、应用分身、工作资料需真机验证。耗电增量尚未实测。

## 真机验收清单

1. 关闭白名单，确认原有键盘显示设置和自家应用常显不变。
2. 不选择其他应用，确认自家应用固定开启、不可取消，其他应用中无球、无透明触摸遮挡。
3. 只选择聊天应用：进入时遵循原有规则；桌面、浏览器、设置中隐藏。
4. 第三方键盘与自家键盘反复切换、打开搜索框，检查宿主应用没有被键盘或搜索浮窗替换，白名单应用内的球继续遵循原有规则。
5. 点击/长按/拖动球期间离开白名单应用，检查保护期不阻止隐藏且无延迟动作。
6. 打开通知栏、最近任务、锁屏再解锁，确认无残留且回到白名单能恢复。
7. 修改白名单开关，检查立即生效且条目不移动；返回再进入，确认已开启的应用置顶。分享白名单执行同样检查。
8. 关闭再开启无障碍、旋转屏幕、重启应用，检查初始化不闪现。
9. 分屏/小窗中同时打开白名单与非白名单应用，来回点击操作，确认球跟随当前焦点应用切换，并继续遵循键盘显示规则；测试后台 PiP 不影响正在操作的应用。
10. 在分屏白名单应用中打开搜索框或键盘，确认宿主仍被识别；关闭宿主窗口、切换到未选应用或展开系统界面，确认历史宿主不阻止隐藏。
11. 静置、打字和刷页面时观察 CPU/日志，确认没有持续重试或重复窗口更新。
12. 在两个白名单页面分别搜索中文应用名、大小写混合的包名片段和不存在的关键词，确认结果与空状态正确；切换结果中的开关后清空搜索，确认选择已保存、排序不变，悬浮球页面的自家应用仍固定开启。应用加载期间输入关键词，加载结束后也应按当前关键词筛选。

单元测试覆盖准入规则、键盘/自家浮窗、系统焦点、多窗口、未知窗口和应用切换。
单元测试不能代替真机对窗口事件时序与触摸穿透的验证。
