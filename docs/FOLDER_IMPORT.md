# 文件夹批量导入

分类仍为单层。用户选择的目录决定分类粒度：

- 所选目录直接包含的图片，归入该目录同名分类。
- 每个一级子文件夹对应一个分类；其下所有层级的图片均归入该分类。
- 纯容器目录、空目录，以及没有任何图片成功导入的目录，不创建分类。
- 同名分类复用；确认弹窗展示各分类的候选图片数及新建/合并提示。数量包含尚未解码和去重的候选文件。
- 从指定分类进入导入时，图片同时加入原目标分类，保持已有行为。
- 导入结束后，没有有效自定义图标的分类使用其当前显示顺序第一张图片作为图标（保存为 `res:<资源ID>`）。采用完成导入后的分类内排序，不采用扫描顺序；已有有效图标保留。取消时为已保留的图片补上分类图标，空分类不设置图片图标。

例如选择 `Stickers`：

| 来源 | 分类 |
| --- | --- |
| `Stickers/a.png` | `Stickers` |
| `Stickers/猫猫/b.png` | `猫猫` |
| `Stickers/猫猫/动图/搞笑/c.gif` | `猫猫` |
| `Stickers/狗狗/搞笑/d.png` | `狗狗` |

若改为选择 `Stickers/猫猫`，其中直接图片归入 `猫猫`，`动图` 子树的图片归入 `动图`。

系统预留名称 `全部`、`最近`、`ALL`（忽略大小写）不创建分类。文件提供程序未返回目录名时沿用根分类；根目录本身没有可用名称时直接导入资源库。

扫描在后台使用队列遍历，避免深层目录造成递归栈溢出，并跳过已经访问的目录 ID。保留原有图片格式筛选和资源去重机制；同一来源只读取一次，但保留其所有分类关系。一个子目录读取失败时继续其他分支，并在预览和完成摘要中提示扫描不完整及失败路径；根目录无法读取时直接报错。

图片读取、解码和编码按设备测评结果采用 1、2 或 4 路并发，按来源顺序逐张提交。32 张及以上的导入会先用固定的 192×192 小图运行与导入相同的解码、像素哈希、PNG 编码和文件哈希流程，预热后比较各档完成相同 8 次处理的耗时。增加并发需比当前最佳档位至少提高 15% 吞吐量，避免多开线程反而更慢。测评以 350ms 为停止启动新档位的预算、500ms 为协程超时；已经开始的原生图像操作完成后才释放 Bitmap，因此不是严格的 500ms 硬上限。测评不写入资源或图片文件；不足 32 张、低内存设备或当前资源受限时直接单路导入。测评失败或无有效结果也回退到单路。

并发上限同时受 CPU 核数、应用堆上限和剩余堆空间约束。导入期间每 500ms 最多检查一次内存和系统温度，内存紧张或系统报告中度及以上温度压力时降低并发，待已启动任务排空后执行更低档位；状态恢复后最多恢复到测评选中的档位。Android 10 及以上使用系统温度状态；更早版本仅使用内存保护。图片预处理另外按尺寸和源文件大小估算临时内存，以应用堆上限的三分之一作为并行预算；超过预算的大图单独解码编码，避免小图测评选中的并发数直接用于多张大图。该估算不保证任意尺寸的单张图片都能解码。

静态图先计算像素 MD5 并查重，已存在时跳过 PNG 编码；入库事务内再次检查去重，防止预处理抢跑或并发导入产生重复。如果预处理命中的资源随后被删除，会重新使用保留的来源数据完成导入。

每张图片的资源记录和分类关系在同一个短事务内及时提交，文件写入及完整 MD5 回读校验在事务外完成。事务失败或最终发现重复时删除暂存文件。取消时先完成当前图片的事务；取消或发生数据库错误后不触发原图清理。进程被系统终止不提供自动续传，可重新选择来源进行去重导入并补全分类。

数据库 v4 为全局排序和分类内排序新增索引，避免每张图片查询最小排序值时重复扫描。导入结束或中断后记录总耗时及计数；诊断日志按 250ms 窗口合并写入，避免逐条读写日志文件。

## 验证

`FolderImageScannerTest` 覆盖三级嵌套、重新选择根目录、根目录图片、空目录、MIME/扩展名识别、不可读分支、根目录错误、循环目录、共享来源、2000 层嵌套及取消。

`OrderedImportPipelineTest` 验证并发预处理、提交顺序、预取上限、单项失败及取消；`ResourceHashStreamTest` 验证流式 MD5 和既有 MD5 值一致。设备测试 `ImportPipelineTest` 覆盖重复图跳过编码、预处理期间删除资源、并发去重、失败回滚及取消时分类完整性，`DatabaseMigrationTest` 验证 v3→v4 数据保留和查询使用索引。

`ImportParallelismPolicyTest` 验证测速选择、无明显收益维持低档、缺失结果回退，以及 CPU/内存/温度限制；`ImportPreparationBudgetTest` 验证大图独占、取消和失败后释放预算。`OrderedImportPipelineTest` 另覆盖动态降低并发时先排空、恢复时不超过测评上限。设备上还需检查测评耗时、不同档位选择及温度/内存压力下的降档。

设备回归时，准备上表目录结构，使用系统文件夹选择器选择 `Stickers`，确认分类预览、实际图片归属及同名分类复用。再选择 `猫猫` 验证分类边界变化。另需验证扫描/确认/导入时旋转屏幕、后台返回、取消后重新导入，以及特定文件提供程序的权限错误；JVM 测试不替代这些设备检查。
