# 相似图片清理

首页独立卡片进入，点击「开始扫描」才进行扫描。支持全部资源和指定分类，并可选择全部图片、仅静态图或仅动图（GIF）。默认全部，静态图和动图分别比较。

## 产品规则

- 结果仅表示疑似相似，不显示相似度百分比，也不评价图片优劣。
- 不默认勾选、不推荐保留、不自动删除。图片按资源 ID 固定顺序显示，缩略图完整显示，勾选区域不遮挡图片。
- 点击图片进入现有详情页，在同组内逐张查看尺寸、大小、分类等客观信息。
- 动图缩略图和详情页可播放；结果组标识静态图/动图，每张动图显示单次播放时长和尺寸。
- 匹配范围从严格到宽松，松开滑条后重新匹配已有特征，不重新解码图片。重新匹配清空勾选。
- 批量删除复用现有 ResourceDeleteHelper，确认删除后移除资源记录、分类关联和本地文件。删除后刷新结果。
- 扫描和匹配可取消；配置变更由 ViewModel 保留状态。离开页面后不启动长期后台任务。

## 特征与匹配

独立于 ResourceHasher、MD5 和 syncKey，不参与导入去重、同步身份或资源包导入导出。

图片先降采样以限制内存，再缩放为 32 × 32，透明像素统一合成到白底。基于灰度图低频 DCT 生成 Long 特征，排除直流分量，使用 63 个 AC 系数和一个固定零位。以汉明距离判断候选。沿用库内图片方向，不修改或重新编码源文件。

滑条对应距离阈值 0–16，默认 6。这是候选筛选参数，不是视觉相似概率；默认值仍需结合实际表情包反馈调校。相同底图不同文字、纯色图、不同颜色的相同轮廓可能匹配；明显裁切、镜像、旋转可能漏检。

BK 树检索避免存储全量两两比较结果，宽松阈值下仍可能退化为大量比较。按 ID 顺序贪心分组，每个成员必须与组内第一个资源直接匹配，每张图片仅显示一次。组内并不保证任意两张都达到阈值，也不枚举跨组的所有相似关系；这种边界避免链式聚合和同一资源重复勾选。

## 缓存

动图使用现有 Glide GIF 解码器，按帧顺序解码并处理透明、局部帧与 disposal 合成，不转码、不改变源文件。以一个播放周期的 0、1/8、…、7/8 时间点采样，计算 8 个 pHash；至少 7 个对应时间点的汉明距离必须达到滑条阈值。短动图允许同一帧覆盖多个采样点。匹配按播放进度归一化，不限制总时长；相同内容整体加速/减速可匹配。循环起点偏移、裁切、局部速度变化不做时间对齐，短于采样间隔的差异可能漏检。

动图采用可取消的逐对匹配和相同的固定基准分组规则，不使用首帧作为资源身份。所有帧都解码以检查损坏并正确合成采样帧，只缓存采样特征，解码位图及时回收。

使用 cacheDir/similarity-v1.db 独立 SQLite 缓存，以资源 ID、syncKey、fileMd5、文件长度和修改时间校验。只在扫描时计算缺失或失效的条目，取消后已完成条目仍可复用。缓存可由系统或用户清除，清除后自动重算；算法或预处理改变时必须升级缓存版本。

缓存 schema v2 增加多帧特征和时长字段，保留已有静态图特征。动图缓存签名带 animation-v1，避免与静态图缓存混用。

## 验证

- 单元测试：亮度/对比度变化、平坦图稳定性、结构变化、BK 树与穷举比较、分组不链式聚合、边界与取消。
- 动图单元测试：按时间采样、帧率/整体速度变化、首帧相同后续不同、7/8 阈值边界、分组与取消。
- Android 测试：缩放/透明底、缓存复用、文件变化失效、损坏/缺失文件、页面进入和重建不自动扫描或选择。
- Android 测试图像及缓存使用独立临时目录，不写入用户资源库。
